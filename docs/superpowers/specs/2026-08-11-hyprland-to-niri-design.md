# Hyprland → Niri Migration Design

**Date:** 2026-08-11
**Status:** Approved

## Goal

Switch the daily-driver compositor from Hyprland 0.56 to Niri 26.04 while keeping the
custom Quickshell rice (bar, lock screen, launcher, notifications, clipboard, calendar,
music, orb, gamebar, screenshot overlay). Hyprland remains installed and bootable as a
fallback session until the Niri session is fully trusted.

## Approach

**Parallel sessions, dual-compositor rice.** Niri installs alongside Hyprland as a second
SDDM session. The rice is not forked: the small set of Hyprland-specific touchpoints gets
a compositor abstraction so the same Quickshell tree runs under both compositors.

Rejected alternatives:
- *Fork the rice per compositor* — double maintenance, drift guaranteed.
- *Full DE (Plasma/COSMIC)* — retires the rice; explicitly not wanted.
- *Sway/River* — run Quickshell fine but don't change the workflow, which was half the
  point of switching.

## Current-state inventory (measured, not assumed)

- **Hyprland-specific rice files (9):** `Config.qml`, `TopBar.qml`, `Lock.qml`,
  `watchers/kb_fetch.sh`, `deskicon/Icon.qml`, `applauncher/appLauncher.qml`,
  `wallpaper/WallpaperPicker.qml`, `settings/SettingsPopup.qml`, plus `qs_manager.sh`.
  Everything else in `~/.config/hypr/scripts/quickshell/` is compositor-agnostic.
- **`qs_manager.sh`** touches Hyprland only in the fast-path workspace switch
  (`hyprctl dispatch workspace/movetoworkspace N`). All other routing is Quickshell IPC.
- **Keybinds:** 73, in autogenerated `keybindings.conf`. Most exec scripts or
  `qs_manager.sh`; only a handful use raw dispatchers (killactive, togglefloating,
  resizeactive, movewindow, movefocus).
- **Settings pipeline:** `keybindings.conf`, `settings.conf`, `autostart.conf` are
  **autogenerated from `settings.json`** by the rice's settings system
  (`settings_watcher.sh`). The Niri config will initially be hand-maintained, NOT
  generated (see Out of scope).
- **Input:** `us,th` layouts, `grp:alt_shift_toggle`, heavy touchpad tuning,
  sensitivity 0.2 adaptive.
- **Monitor:** eDP-1 1920x1080@144.
- **Rules:** window rules (launcher float/center/1200x600, qs-master float,
  spotify/vesktop opacity 0.70/0.60) and ~12 layer rules, most applying **blur** to
  Quickshell layer namespaces — the "Liquid Glass" look.
- **Autostart:** fully portable (hypridle, hyprpolkitagent, swayosd, cliphist,
  playerctld, awww-daemon, kdeconnect, rice daemons). None are Hyprland-locked.
- **Env:** NVIDIA PRIME offload vars, qt6ct, ozone hints — compositor-agnostic,
  carried over verbatim.

## Components

### 1. Niri stow package (`~/dotfiles/niri/.config/niri/config.kdl`)

Hand-written KDL config porting: output config, input (layouts, toggle, touchpad),
environment, spawn-at-startup (same list as autostart.conf), all 73 keybinds, window
rules, layer rules (as supported), screenshot/hotkey basics. Validated with
`niri validate` before first login.

### 2. Compositor abstraction in the rice

`CompositorService` singleton in the Quickshell tree exposing: workspace list + focused
workspace, active window (title/class), and a `dispatch(action)` method. Backend chosen
at startup: `Quickshell.Hyprland` when `HYPRLAND_INSTANCE_SIGNATURE` is set, Niri JSON
IPC over `$NIRI_SOCKET` (event-stream) otherwise. The 7 QML files switch from direct
`Quickshell.Hyprland` use to this service; `kb_fetch.sh` and `qs_manager.sh` get an
equivalent shell-level branch (`niri msg` vs `hyprctl`).

### 3. Session/boot integration

Niri package ships `niri.desktop`; SDDM picks it up with zero config. `niri-session`
(systemd) is the login target so `dbus-update-activation-environment` behavior matches
what `session.conf` did under Hyprland.

## Error handling / risks

- **Blur is the aesthetic risk.** The glass look depends on Hyprland layer-rule blur.
  Verify what niri 26.04 supports for layer-surface blur *before* porting visuals; if
  absent, fallback is raising surface opacity in `Glass.qml` (config value, not a fork).
- **Session safety:** Hyprland session untouched throughout; worst case at any point is
  "log back into Hyprland".
- **Dual-backend regressions:** every rice change must keep the Hyprland path working
  (test by launching quickshell under the current Hyprland session after each change).

## Testing

- `niri validate` green before first login.
- Phase 1 gate: log into Niri, keyboard layouts toggle, terminal opens, workspace keys
  work, xwayland-satellite runs a Steam/X11 app.
- Phase 2 gate: bar shows correct workspaces under BOTH compositors; lock screen locks
  and unlocks under Niri (`ext-session-lock`); launcher/clipboard/notifications open.
- Phase 3 gate: screenshot overlay, watcher daemons, window rules behave; a full day's
  driving on Niri without reaching for the Hyprland session.

## Out of scope (YAGNI)

- Regenerating `config.kdl` from `settings.json` (the settings-app pipeline). Revisit
  only after Niri becomes the daily driver.
- Porting Hyprland-specific animations config; Niri's defaults are used initially.
- Removing Hyprland. Not until weeks of stable Niri use.

## Phases

1. **Bootable Niri session** — install `niri` + `xwayland-satellite`, write + validate
   the stow package, first login, blur status check.
2. **Rice on Niri** — CompositorService, port the 9 files, verify lock/bar/launcher.
3. **Polish + commit** — remaining rules, overlays, daemons, dotfiles commit.
