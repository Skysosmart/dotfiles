# GNOME 50 Rice Design

**Date:** 2026-08-25
**Status:** Approved

## Goal

Turn the GNOME 50 Wayland session into a minimal, keyboard-driven, scrollable-tiling
desktop that is **fully independent of the Hyprland rice**. GNOME becomes a first-class
session in `~/dotfiles` with its own stow package, its own shell theme and its own
keybinds — sharing nothing that would have to be unpicked later if either session is
retired.

The Hyprland rice is not modified by this work. Not one file under `hypr/` is touched.

## Approach

**A self-contained `gnome/` stow package plus an apply/dump script pair.**

GNOME keeps its configuration in dconf, a binary database that stow cannot manage. So
the package stores a text `dconf.ini` holding *only the keys we own*, and two idempotent
scripts move config in both directions: `apply.sh` loads it, `dump.sh` writes live state
back. The repo can therefore never silently drift from the running session.

Rejected alternatives:
- *Auto-apply via a systemd user service* (`gnome-rice.service` bound to
  `gnome-session.target`, mirroring the old `inir.service`) — self-healing, but it
  silently reverts any live tweak at next login and adds a unit to debug. Deferred; add
  later only if drift proves to be a real problem.
- *GUI-first with dump only* — least friction, but leaves no reproducible path from a
  fresh install to the rice, which is the point of the repo.
- *`gschema.override` at the system level* — needs root, applies only as defaults (user
  dconf still wins), and handles extension settings poorly.
- *Integrating GNOME into the matugen pipeline* — was the original plan and was
  explicitly reversed. See "Separation" below.

## Separation from Hyprland

The decisive constraint, measured rather than assumed:

**GTK theming is per-user, not per-session.** `~/.config/gtk-3.0/gtk.css`,
`~/.config/gtk-4.0/gtk.css` and the `org.gnome.desktop.interface` keys (`gtk-theme`,
`icon-theme`, `cursor-theme`, `font-name`, `color-scheme`) are read by every GTK app
regardless of which session launched it. There is no per-session scoping.

| Genuinely separable | Unavoidably shared |
|---|---|
| GNOME Shell chrome (`~/.themes/…/gnome-shell.css`) | GTK3/GTK4 app colors (`gtk.css`) |
| Extensions and their settings | icon / cursor / font themes |
| All keybinds (GNOME-only dconf paths) | `color-scheme` (light/dark preference) |
| Wallpaper (`org.gnome.desktop.background`) | |

Decision: **GNOME owns its shell chrome; GTK stays shared and matugen-owned.** The
GNOME shell theme is hand-authored, static, committed, and never generated. No matugen
template is added, `matugen_reload.sh` is not edited, and no path under `hypr/` is
referenced. Deleting this rice is `git rm -r gnome/`.

Consequence accepted: GTK apps look identical in both sessions. Only the shell chrome
differs. This is a constraint of GTK, not a design shortcut.

## Current-state inventory (measured, not assumed)

- **GNOME 50 is already installed and bootable:** `gnome-shell 1:50.4-1`, `mutter 50.4-1`,
  `gnome-session 50.1-1`, selectable in SDDM alongside Hyprland and Plasma. No `gdm`,
  no `gnome-control-center`.
- **Zero extensions enabled.** `org.gnome.shell enabled-extensions` is `@as []`; only
  `gsconnect` is installed at all.
- **The session already inherits the shared GTK layer** — `adw-gtk3-dark`,
  `WhiteSur-dark` icons, `Bibata-Modern-Ice` cursor, `Roboto Flex 11`. This is why it
  does not look stock.
- **Wallpaper is stock** `/usr/share/backgrounds/gnome/adwaita-l.jxl`.
- **Terminal is `kitty`** (Hyprland binds `$mainMod, RETURN, exec, kitty`).
- **Pre-existing bug, in scope to note but not fix here:** the live
  `~/.config/gtk-4.0/gtk.css` was last written by iNiR (header reads "Generated by iNiR
  theming") and carries a *light* palette (`--window-bg-color: #fbf9f5`) while GNOME asks
  for `prefer-dark`. matugen's mode defaults to `dark` and `init.sh` passes no `-m`, so
  re-running matugen regenerates it correctly. One command, tracked separately.

## Package layout

```
gnome/.config/gnome-rice/
├── dconf.ini      # only the keys we own, text, diffable
├── apply.sh       # dconf load per-subtree + enable exts + set theme (idempotent)
├── dump.sh        # live state -> dconf.ini
├── bootstrap.sh   # pacman/yay packages + out-of-repo extensions at pinned versions
└── README.md      # what this is, how to re-apply
gnome/.themes/Zaru-Dark/gnome-shell/gnome-shell.css
```

PaperWM and Clipboard Indicator install into
`~/.local/share/gnome-shell/extensions/` and are **deliberately not stowed or
committed** — they are upstream code, the same category as a plugin. Vendoring them
would wreck the repo's diffs. `bootstrap.sh` pins the versions instead.

## Config mechanism

`dconf.ini` covers only these subtrees, so GNOME upgrades adding new defaults never show
up as repo churn:

| dconf path | What we set |
|---|---|
| `/org/gnome/shell/` | `enabled-extensions` (the four) |
| `/org/gnome/shell/extensions/user-theme/` | `name='Zaru-Dark'` |
| `/org/gnome/shell/extensions/paperwm/` | layout + keybindings |
| `/org/gnome/shell/extensions/clipboard-indicator/` | `toggle-menu`, `enable-keybindings` |
| `/org/gnome/desktop/wm/keybindings/` | close, workspace switch/move, cleared defaults |
| `/org/gnome/shell/keybindings/` | overview, screenshot, cleared defaults |
| `/org/gnome/mutter/keybindings/` | cleared tiling defaults |
| `/org/gnome/mutter/` | `dynamic-workspaces=false` |
| `/org/gnome/desktop/wm/preferences/` | `num-workspaces=9` |
| `/org/gnome/settings-daemon/plugins/media-keys/` | app launchers, lock, logout |
| `/org/gnome/desktop/interface/` | font, cursor, icons, color-scheme |
| `/org/gnome/desktop/background/` | wallpaper |

`apply.sh` runs `dconf load` **per-subtree**, never one global load, so it cannot clobber
unrelated GNOME state. Both scripts consume a single shared list of paths, so they cannot
drift apart.

## Extensions

| Extension | Channel | Pin | Why this channel |
|---|---|---|---|
| **PaperWM** | upstream installer | `v50.0.1` | AUR `-git` is stuck at v47.1.0, three releases behind |
| **User Themes** | pacman | `gnome-shell-extensions 50.3-1` | in `extra`, version-matched to the shell |
| **AppIndicator** | pacman | `gnome-shell-extension-appindicator 1:65-1` | in `extra` |
| **Clipboard Indicator** | AUR (yay) | `71-1` | last modified 2026-05-30, *fresher* than upstream's own tags (v44, 2022); the `-git` variant is stale (Nov 2023) |

The channels differ per extension because freshness differs per extension — verified
individually, not assumed. `metadata.json` for PaperWM v50.0.1 declares
`shell-version: [45,46,47,48,49,50]`; Clipboard Indicator's master declares
`[46,47,48,49,50]`.

**`bootstrap.sh` asserts after install** that each extension's `metadata.json` lists
shell-version `50`, and fails loudly if not — two of these channels have already been
found stale once, so this is checked rather than trusted.

Deliberately excluded: **Blur My Shell** — wrong for "minimal", and shell-wide blur is
continuous GPU load on a machine with a documented history of EGL/cross-GPU faults.

## Keybind map

Full parity with the niri layout, resolved in favour of existing muscle memory.
PaperWM's defaults already match ~19 binds exactly; those are listed as "default".

### PaperWM (`/org/gnome/shell/extensions/paperwm/keybindings/`)

| Intent | Bind | PaperWM action | Change |
|---|---|---|---|
| focus column left/right | `Super`+`←`/`→` | `switch-left` / `switch-right` | default |
| focus window up/down | `Super`+`↑`/`↓` | `switch-up` / `switch-down` | default |
| focus, vim keys | `Super`+`H`/`J`/`K` | `switch-left` / `-down` / `-up` | add binding |

**`Super`+`L` is deliberately NOT `switch-right`.** It stays bound to lock, matching an
explicit comment in the niri config ("Mod+L locks like the old dotfiles; column-right
still on Mod+Right"). The vim focus row is `H`/`J`/`K` only — this asymmetry is
intentional, not an oversight.

| first / last column | `Super`+`Home`/`End` | `switch-first` / `switch-last` | default |
| move column/window | `Super`+`Shift`+arrows | `move-left/right/up/down` | remap from `Super`+`Ctrl` |
| move, vim keys | `Super`+`Shift`+`H`/`J`/`K`/`L` | `move-left/down/up/right` | add binding |
| focus monitor | `Super`+`Ctrl`+arrows | `switch-monitor-*` | remap from `Super`+`Shift` |
| move to monitor | `Super`+`Ctrl`+`Shift`+arrows | `move-monitor-*` | default |
| workspace up/down | `Super`+`Page_Up`/`Down` | `switch-up/down-workspace` | default |
| move to workspace up/down | `Super`+`Ctrl`+`Page_Up`/`Down` | `move-up/down-workspace` | default |
| cycle column width | `Super`+`R` | `cycle-width` | default |
| reset height | `Super`+`Ctrl`+`R` | `cycle-height` | remap |
| center column | `Super`+`C` | `center-horizontally` | default |
| maximize column | `Super`+`D` | `toggle-maximize-width` | remap from `Super`+`F` |
| fullscreen | `Super`+`Shift`+`F` | `paper-toggle-fullscreen` | default |
| column width ∓ | `Super`+`-`/`=` | `resize-w-dec` / `resize-w-inc` | remap `inc` to `equal` |
| window height ∓ | `Super`+`Shift`+`-`/`+` | `resize-h-dec` / `resize-h-inc` | default |
| consume / expel | `Super`+`[`/`]` | `slurp-in` / `barf-out` | remap from `Super`+`I`/`O` |
| float window | `Super`+`A` | `toggle-scratch-window` | remap from `Super`+`Escape` |
| float/tile focus | `Super`+`Shift`+`V` | `toggle-scratch` | remap |

Unbound outright: `new-window` (frees `Super`+`Return`), `take-window` (frees
`Super`+`T`), `close-window` (GNOME's own `close` owns this instead — one owner).

### GNOME window manager (`/org/gnome/desktop/wm/keybindings/`)

| Intent | Bind |
|---|---|
| close window | `['<Super>q', '<Alt>F4']` |
| switch to workspace 1–9 | `['<Super>1']` … `['<Super>9']` |
| move to workspace 1–9 | `['<Super><Ctrl>1']` … `['<Super><Ctrl>9']` |

**Fixed workspaces are required.** GNOME 50 ships *dynamic* workspaces, which grow and
shrink on demand — under that model `Super`+`5` on an empty desktop does nothing, so
half the workspace binds would silently fail. The rice therefore sets
`org.gnome.mutter dynamic-workspaces = false` and
`org.gnome.desktop.wm.preferences num-workspaces = 9`, matching the 9 workspaces the
niri layout used.

### GNOME Shell (`/org/gnome/shell/keybindings/`)

| Intent | Bind |
|---|---|
| overview | `['<Super>grave']` |
| screenshot UI | `['<Super><Shift>s']` |

### Launchers (`/org/gnome/settings-daemon/plugins/media-keys/`)

| Intent | Bind | Mechanism |
|---|---|---|
| terminal (kitty) | `Super`+`Return` | `custom0` |
| terminal (kitty) | `Super`+`T` | `custom1` |
| firefox | `Super`+`F` | `custom2` |
| nautilus | `Super`+`E` | `custom3` |
| lock | `Super`+`L` | built-in `screensaver` |
| logout | `Super`+`Shift`+`E` | built-in `logout` |

App launchers are clunky by necessity: GNOME has no first-class "run this command"
binding, so each costs three keys (`name`, `command`, `binding`) under
`custom-keybindings`. This is precisely why `dconf.ini` is the right format rather than
a hand-written `gsettings` script.

### Clipboard Indicator

`toggle-menu = ['<Super>v']`, `enable-keybindings = true`.

### GNOME defaults that MUST be cleared

Easy to forget and they fail silently — a bind simply does nothing, or does the wrong
thing. Each of these collides with something above:

| Default | Key | Collides with |
|---|---|---|
| `org.gnome.shell.keybindings show-applications` | `Super`+`A` | float window |
| `org.gnome.shell.keybindings toggle-message-tray` | `Super`+`V` | clipboard history |
| `org.gnome.desktop.wm.keybindings minimize` | `Super`+`H` | focus left |
| `org.gnome.desktop.wm.keybindings toggle-maximized` | `Super`+`↑` | focus up |
| `org.gnome.desktop.wm.keybindings unmaximize` | `Super`+`↓` | focus down |
| `org.gnome.desktop.wm.keybindings switch-input-source` | `Super`+`Space` | reserved |
| `org.gnome.mutter.keybindings toggle-tiled-left` | `Super`+`←` | focus column left |
| `org.gnome.mutter.keybindings toggle-tiled-right` | `Super`+`→` | focus column right |

Note: the Thai input toggle is `Alt`+`Shift` and is unaffected by clearing
`switch-input-source`.

### Dropped — no GNOME equivalent

`controlPanel`, `sidebarRight`, `cheatsheet`, `wallpaperSelector`, `panelFamily`,
`overview toggle`, `region ocr`, `region search`, `region recordWithSound`, `settings`,
`session menu`. These were all `spawn "inir" …` calls into a shell that no longer
exists. This is the honest cost of retiring iNiR and is accepted.

## Shell theme

A single hand-authored `gnome-shell.css` under `gnome/.themes/Zaru-Dark/gnome-shell/`,
dark, tuned to sit alongside the warm shared GTK palette without being generated from
it. Static, committed, no pipeline. Selected via User Themes
(`org.gnome.shell.extensions.user-theme name='Zaru-Dark'`).

Scope is minimal by design: panel, overview backdrop, popup menus, and PaperWM's
workspace indicators. Not a full Adwaita reskin — GNOME churns shell CSS class names
between releases, and a small surface is a small thing to repair.

## Verification

Automated:
- `bash -n` on `apply.sh`, `dump.sh`, `bootstrap.sh`
- `bootstrap.sh` asserts shell-version `50` in each extension's `metadata.json`
- `dconf.ini` round-trips: `apply.sh` then `dump.sh` produces no diff
- `apply.sh` run twice produces no diff (idempotence)

Manual, and explicitly not automatable:
- log into GNOME and press every ported bind
- confirm the eight cleared defaults no longer fire
- confirm PaperWM scrolling, and that the shell theme loads

## Out of scope

- Any change to the Hyprland rice, `matugen/`, or `hypr/` — including the stale
  `gtk-4.0/gtk.css` light-palette bug, which is tracked separately.
- `gnome-control-center` (not installed; not required by this design).
- Auto-apply systemd unit (rejected above, may be revisited).
- Making GTK app theming differ per session — not possible per the Separation section.

## Risks

- **Extension channel rot.** Two of four channels were found stale during design. The
  `bootstrap.sh` assertion catches it at install time rather than at login.
- **GNOME major upgrades** break shell themes and extension APIs. The theme surface is
  kept deliberately small to limit the blast radius. PaperWM is the main exposure.
- **Keybind verification is manual.** Nothing here can prove a bind works without a
  human pressing it in a live GNOME session.
